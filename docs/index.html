Documentation

Pylon is an execution and risk terminal for Mezo borrowers.

Mezo is a bitcoin-backed CDP: deposit BTC, borrow the MUSD stablecoin. Two properties of the protocol shape everything a borrower can do — debt can only be adjusted by signing with the trove owner's key, and any MUSD holder can redeem against the cheapest-to-redeem trove. Pylon turns both facts into usable operations.

1 · The mechanic that makes this necessary

Mezo's redemption works like Liquity's: a holder of MUSD can always exchange it for $1 of BTC from the protocol, taken from the trove with the lowest collateralisation ratio that is still above the 110% minimum (MCR). The protocol keeps that order in a contract called SortedTroves, which is the single most important object for a borrower to understand.

A redemption repays the tail trove's debt and takes an equal value of its BTC. The borrower's debt falls, their collateral falls, and their ICR moves up slightly — but they have lost exposure to BTC without choosing to. For a position at 111%, a routine redemption is an involuntary sale.

The number that matters is therefore not “am I healthy?” but how much redemption volume stands in front of me. Pylon calls that the buffer ahead, and prints it for every trove in the queue, next to the walk that is currently consuming it.

2 · Three operations, one mechanism

Each operation borrows MUSD from a Tigris flash pool, uses it for one leg, and settles the loan before the transaction returns. Nothing needs to be sitting in the wallet, and a failure at any leg reverts the whole thing.

Flash Loop

Borrow against the trove, buy BTC with the proceeds, post it back as collateral. The position gets larger and the ICR is unchanged apart from fees. Blocked below the 150% CCR, because emitting new debt there is what pushes a trove into recovery mode.entry point: loopSigned(LoopRequest)

Flash Unwind

Repay debt out of the trove's own collateral with zero MUSD in the wallet: the venue fronts the MUSD, the released BTC buys it back, the surplus stays with the borrower. Above 100.3% ICR the ratio improves with every unit repaid.entry point: unwindSigned(UnwindRequest)

Flash Exit

Close the trove entirely. The venue flashes the outstanding debt less Mezo's gas compensation, the collateral buys that MUSD back, the trove closes, and the remaining BTC plus the released compensation are swept to the wallet.entry point: closeSigned(CloseRequest)

3 · The redemption shield

Operations are reactive: they fix a position after the fact. The shield is the proactive half. A Pylon position stores a policy — an ICR trigger, an ICR target and a per-call ceiling — and a MUSD reserve stands behind it. When the position's ICR enters the band, anyone can call defend(); the reserve lends MUSD, and the position spends it on repaying its own debt until the target is reached.

  • The reserve can only ever call lendTo(position), and the position can only spend it on repayMUSD for its own trove.
  • A loan blocks withdrawCollateral and executeClose until it is settled, so the claim is enforced in code, not by trust.
  • Defence must improve the ratio or it reverts — a defence call cannot make a position worse.
  • Reserve lenders receive non-transferable shares priced at total assets over total shares. Flash fees accrue to the pool; defence loans are the risk.

4 · What an operation costs

Fees are charged on the flashed notional, not on the borrowed balance, so a loop on a trove with no MUSD in the wallet costs a fraction of a percent of the amount it moves.

A flash unwind on a 2,211 MUSD debt therefore costs roughly 5–6 MUSD in combined fees, of which nothing has to be held in advance. The X-ray in the Position Architect prints the exact figure for any size before anything is signed.

5 · Security model

  • No custody, no rehypothecation. Pylon never holds collateral or MUSD between transactions, and it has no allowance over any asset.
  • Signature-bound authorisation. Trove changes are authorised with an EIP-712 struct (AdjustTrove / CloseTrove) verified by Mezo's own BorrowerOperationsSignatures contract. It is bound to the owner, the recipient, a nonce and a deadline, so a signature cannot be replayed or retargeted.
  • Two broadcast routes, one rule. The engine service may relay a transaction, but it can only relay what the signature already authorises. Self-broadcast uses the same struct, sent directly from the wallet.
  • Target allowlist. Before a wallet transaction is sent the terminal checks the destination against the deployed Pylon and Mezo addresses, and refuses anything else.
  • Slippage and health floors. Every operation carries a minimum post-operation ICR, and the swap legs carry a minimum output. Both are visible in the X-ray before signing.
  • Revert, do not half-finish. Flash liquidity and health checks happen inside the same transaction, so a failed operation costs gas rather than leaving a position in an intermediate state.
  • Trust surface to acknowledge. The terminal reads state through the public Mezo RPC and the engine service. If both lied, the numbers shown would be wrong — the explorer-linked proof ledger exists so any row can be checked independently.

7 · Agents and the paid report

A keeper that wants to defend a trove needs one fact before it spends anything: where that trove sits in the redemption queue. The engine sells exactly that as an x402 resource — GET /api/v1/x402/trove-report/:address — priced in MUSD on Mezo.

  • Challenge. An unpaid request returns HTTP 402 with an accepts[] entry (scheme exact, network eip155:31611, asset MUSD, a pay-to address and a price), plus the same payload base64-encoded in the PAYMENT-REQUIRED header.
  • Settlement, trustlessly. The terminal sends a real MUSD transfer from the wallet and retries with X-PAYMENT-TX: <hash>; the service verifies the transfer against Mezo before answering. No facilitator, no custody.
  • Settlement, signed. Alternatively the payer signs an EIP-3009 transferWithAuthorization and the engine's facilitator redeems it. Both routes are implemented; the on-chain transfer works on any deployment.
  • The resource. A JSON report: queue rank, MUSD buffer ahead, health band, collateral value, debt, liquidation price and the block the telemetry was computed at.

8 · Limits and roadmap

  • Shielding a native Mezo trove needs that trove to be operated by a Pylon position; today the terminal offers to create one and open its trove, and documents the migration instead of faking it.
  • Unwind and exit accept an approximate collateral ceiling, refined by the engine's previews at quote time; the swap “exact out” leg is what pins the final numbers.
  • The engine API is optional. Without it the terminal runs read-only against RPC for everything except quote sizing, which then uses the engine's own on-chain preview functions.
  • Next: multi-trove portfolios with a combined health view, scheduled shield defences, a keeper incentive funded by the reserve, and cross-trove unwinds that move debt to the healthiest position first.

9 · Reproduce it

git clone <repo> && cd web
pnpm install
pnpm typecheck       # strict TS, no implicit any, no unchecked index access
pnpm build           # static export → ./out
pnpm preview         # serve the exported bundle

# optional: point the terminal at a running engine service
NEXT_PUBLIC_API_BASE=http://localhost:8787 pnpm dev

Every contract address used by the terminal is listed on the proofs page and on chain: engine 0x901198cD4EE9086997D839401f361518cAE46ed6, reserve 0x53a0206A307E084AdA2eB24346463cf4E14C5131.
